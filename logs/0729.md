# Experiment 1
由於 CortexDC 匯出的 InfluxDB 資料為 long format，每筆資料僅代表單一時間、單一 measurement 與 field 的數值，因此模型訓練前需先進行資料轉換。第一版 以時間與 server_name 作為索引，將 server_temperature、server_power、server_fan 與 server_cpu 等資料整合為 wide format。CPU temperature 由 sensor_name 中包含 CPU Temp、CPU1 Temp、CPU2 Temp 或 CPU package temperature 的感測器取得，並排除 VRM、DIMM、PCH、Peripheral 與 System 類型感測器；inlet temperature 則由 Inlet Temp、Inlet Ambient 或 System Board Inlet Temp 取得。若同一時間點存在多個 CPU 或風扇感測器，則取平均值作為該時間點的代表值。
- 輸入：目前與過去的 CPU 溫度、進氣溫度、server power、fan rpm
- 輸出：未來第 10 筆有效觀測點的 CPU 溫度
- 資料：8 台 server 的 CortexDC 資料
- 處理：多 sensor 合併成代表值，非 CPU 溫度排除
- 切分：70% train、15% validation、15% test

## Experiment 01 與 Experiment 02 比較表

| 項目 | Experiment 01：有效觀測點版本 | Experiment 02：5 分鐘固定取樣版本 |
|---|---|---|
| 實驗目的 | 確認 XGBoost-lag 模型可用於 CPU temperature prediction | 建立具有明確時間意義的 10 分鐘後 CPU temperature prediction |
| 原始資料來源 | CortexDC / InfluxDB CSV | CortexDC / InfluxDB CSV |
| 資料格式 | Long format 轉 Wide format | Long format 轉 Wide format |
| 取樣方式 | 保留有效觀測點 | 重新整理為固定 5 分鐘一筆 |
| 時間間隔 | 不完全固定，依 CortexDC 實際回傳資料而定 | 固定 5 分鐘 |
| Target 定義 | 未來第 10 筆有效 CPU temperature | 實際 10 分鐘後 CPU temperature |
| Horizon 設定 | `PREDICT_HORIZON = 10` | `PREDICT_HORIZON = 2` |
| Horizon 意義 | 第 10 筆有效觀測點 | 2 steps × 5 分鐘 = 10 分鐘後 |
| Input features | `cpu_temp`, `inlet_temp`, `server_power`, `fan_rpm` | `cpu_temp`, `inlet_temp`, `server_power`, `fan_rpm` |
| CPU temperature 處理方式 | 多個 CPU sensor 取平均 | 多個 CPU sensor 取平均，5 分鐘內再取平均 |
| Inlet temperature 處理方式 | 多個 inlet sensor 取平均 | 多個 inlet sensor 取平均，5 分鐘內再取平均 |
| Fan speed 處理方式 | 多顆 fan 取平均 | 多顆 fan 取平均，5 分鐘內再取平均 |
| Server power | `average_consumed_watts` | `average_consumed_watts`，5 分鐘內取平均 |
| Lag 設定 | `LAGS = [0, 1, 5, 10]` | `LAGS = [0, 1, 2]` |
| Lag 時間意義 | 目前、前第 1 / 5 / 10 筆有效資料 | 目前、前 5 分鐘、前 10 分鐘 |
| 模型 | XGBoost Regressor | XGBoost Regressor |
| XGBoost 參數 | 相同 | 相同 |
| 資料切分 | 70% train / 15% validation / 15% test | 70% train / 15% validation / 15% test |
| 切分方式 | 依時間順序切分 | 依時間順序切分 |
| Samples | 2585 | 2252 |
| Train | 1809 | 1576 |
| Validation | 388 | 338 |
| Test | 388 | 338 |
| MAE | 1.008 °C | 0.624 °C |
| RMSE | 1.369 °C | 0.903 °C |
| Max Error | 4.630 °C | 3.977 °C |
| Inference time | 0.000045 sec/sample | 0.000024 sec/sample |
| 優點 | 可快速驗證資料轉換與模型訓練流程是否可行 | 時間軸固定，target 可明確表示為 10 分鐘後 |
| 限制 | `shift(-10)` 不一定代表實際 10 分鐘後 | 使用平均值可能會平滑掉短時間高溫尖峰 |
| 適合作用 | 初步流程驗證 | 後續主要實驗 baseline |

## 簡短說明

Experiment 01 主要用來確認 CortexDC 資料經過前處理後，可以成功建立 XGBoost-lag CPU temperature prediction model。然而，由於資料是依照有效觀測點排列，`shift(-10)` 只能代表未來第 10 筆有效資料，無法保證等於實際 10 分鐘後。

Experiment 02 則將資料重新整理為固定 5 分鐘取樣，因此 `shift(-2)` 可以明確代表實際 10 分鐘後。兩版使用相同的 input features、相同模型與相同資料切分方式，主要差異在於取樣方式與 target 的時間定義。結果顯示，5 分鐘固定取樣版本在 MAE、RMSE 與 Max Error 上皆優於第一版，因此更適合作為後續實驗的主要 baseline。
